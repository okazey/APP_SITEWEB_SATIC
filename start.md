"Conception et mise en place du site web de l’UFR SATIC"

OBJECTIF
Générer un workflow clair, structuré et directement exécutable pour les deux premières phases du Design Thinking :

1. Understanding (Compréhension des besoins utilisateurs)
2. Definition (Définition du problème et cadrage du projet)

Le workflow doit être adapté à un projet réel de création de site web universitaire dans un contexte africain (contraintes techniques, diversité des utilisateurs, accessibilité, gouvernance du contenu).

EXIGENCES

* Fournir un processus étape par étape orienté action
* Détailler précisément ce que chaque groupe doit faire
* Proposer des outils simples et accessibles
* Inclure des livrables exploitables pour leur mémoire
* Intégrer des exemples concrets liés à un site web universitaire (étudiants, enseignants, administration, futurs étudiants)
* Prendre en compte les contraintes réelles :

  * Connexion internet limitée
  * Accès mobile prioritaire
  * Mise à jour du contenu
  * Manque de ressources techniques

STRUCTURE ATTENDUE

1. PHASE 1 : UNDERSTANDING

   Objectif : Comprendre les besoins réels des utilisateurs du futur site web

   Sous-étapes :

   * Identification des parties prenantes (étudiants, enseignants, administration, visiteurs externes)
   * Collecte des besoins
   * Analyse des usages actuels (sites existants ou absence de site)

   Actions concrètes :

   * Réaliser 10–15 interviews utilisateurs
   * Créer un questionnaire simple (Google Forms)
   * Observer comment les étudiants accèdent à l’information actuellement
   * Analyser 3 à 5 sites web d’universités similaires

   Outils recommandés :

   * Google Forms
   * Notion / Google Docs
   * Figma (pour structurer les idées)

   Exemples de questions d’interviews :

   * Quelles informations cherchez-vous le plus souvent ?
   * Quels problèmes rencontrez-vous actuellement ?
   * Préférez-vous accéder via téléphone ou ordinateur ?
   * Quels éléments doivent absolument figurer sur le site ?

   Livrables attendus :

   * Personas (au moins 3 profils types)
   * Carte d’empathie
   * Liste des besoins utilisateurs
   * Synthèse des insights clés

2. PHASE 2 : DEFINITION

   Objectif : Transformer les données collectées en problèmes clairs à résoudre

   Méthodologie :

   * Regrouper les données collectées
   * Identifier les problèmes récurrents
   * Prioriser les besoins critiques

   Actions concrètes :

   * Créer un tableau de synthèse des problèmes
   * Identifier les "pain points" majeurs
   * Rédiger des "Problem Statements"

   Formulation attendue :

   * "Comment pourrions-nous permettre aux étudiants d’accéder rapidement aux informations académiques via mobile ?"
   * "Comment pourrions-nous centraliser les informations administratives de l’UFR SATIC ?"

   Priorisation :

   * Impact utilisateur
   * Faisabilité technique
   * Importance institutionnelle

   Livrables attendus :

   * 3 à 5 Problem Statements clairs
   * Axe principal du projet
   * Cahier de besoins fonctionnels simplifié

3. WORKFLOW GLOBAL

   Timeline (2 à 3 semaines) :

   * Semaine 1 : collecte des données
   * Semaine 2 : analyse et synthèse
   * Semaine 3 : définition du problème

   Répartition des tâches :

   * Groupe 1 : collecte terrain + interviews
   * Groupe 2 : analyse + benchmark + structuration
   * Collaboration sur la définition finale

   Checklist :

   * Interviews réalisées
   * Données analysées
   * Personas créés
   * Problem statements validés

4. BONUS (CRITIQUE MAIS UTILE)

   Recommandations spécifiques :

   * Prioriser le mobile-first
   * Prévoir une interface simple et rapide
   * Anticiper la gestion des contenus (qui met à jour ?)

   Risques à anticiper :

   * Site non maintenu après livraison
   * Mauvaise adoption par les utilisateurs
   * Complexité inutile

   Conseils :

   * Valider rapidement avec de vrais utilisateurs
   * Ne pas surcharger le site
   * Aller à l’essentiel (information claire > design complexe)

STYLE

* Direct, opérationnel, sans théorie inutile
* Orienté terrain et exécution
* Clair et structuré

OBJECTIF FINAL
Les étudiants doivent pouvoir appliquer immédiatement le workflow pour produire une phase Understanding et Definition solide, exploitable dans leur mémoire et utile pour la conception du site web.
